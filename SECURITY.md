# Security Policy

## Overview

Security is a priority for this project. This document explains how to report security vulnerabilities and what to expect from the maintainers.

## Reporting vulnerabilities

Use GitHub Security Advisories only:

[GitHub Security Advisories](https://github.com/barsik0396/shell4/security/advisories)

Do NOT report vulnerabilities via email, issues, pull requests, social media, or other channels.

## What to include in a report

Please include the following when creating an advisory:

- A short description of the issue and its potential impact
- Clear steps to reproduce (PoC) or a minimal test case
- Affected versions/components
- Any relevant logs, error messages, or screenshots
- Whether you would like to be contacted and if you want public credit

## Scope

In-scope:

- Source code contained in this repository
- CI/CD configuration defined in this repo
- Official published artifacts (releases, packages, images) produced by this repo
- Documentation maintained in this repo

Out-of-scope:

- Third-party services or systems outside this repository.

Note on dependencies:

- Upstream-only dependency vulnerabilities (those that affect only the dependency project and do not change how this repository uses, packages, or distributes that dependency) should be reported to the dependency's upstream project and are considered out-of-scope for this repository.
- If a vulnerability affects how this repository uses, packages, or distributes a dependency (for example: insecure packaging, build or integration issues, or repository-specific backports), report it here via GitHub Security Advisories. Maintainers will triage repository-related dependency issues and coordinate with upstream when needed.

## Response times

- Acknowledgement: within 1 business day
- Initial assessment: within 2 business days
- Fix timeline: depends on severity; critical issues targeted within 72 hours, high issues targeted within 7 days

## Confidentiality and responsible disclosure

Do not publish or disclose details publicly until a fix is released and coordinated. The maintainers will work with reporters to agree on disclosure timelines.

## No other reporting channels

Only GitHub Security Advisories will be accepted. Reports sent via other channels will not be processed.

## Acknowledgements

Reporters who help responsibly may be publicly credited unless they request anonymity.
